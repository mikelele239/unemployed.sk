# unemployed.sk — Platform Overview

> Tinder-style career platform for Gen Z in Slovakia.  
> Built with React (Vite), Express.js, and Supabase.

---

## Architecture

```
unemployed.sk/
├── server.js               # Express entry point (~90 lines)
├── routes/
│   ├── jobs.js             # Jobs CRUD, views, applications, AI scoring
│   └── auth.js             # Auth proxies, student/employer profiles, submissions
├── build.js                # Single-command build for all 4 apps + landing
├── apps/
│   ├── landing/            # Static HTML landing page (multi-lang SK/EN)
│   ├── student/            # Live student React app (Supabase-backed)
│   ├── employer/           # Live employer React app (Supabase-backed)
│   ├── student-demo/       # Isolated demo: no auth, mock data
│   └── employer-demo/      # Isolated demo: no auth, mock data
├── dist/                   # Production build output (generated by build.js)
│   ├── app/                → /app
│   ├── employer/           → /employer
│   ├── student-demo/       → /student-demo
│   ├── employer-demo/      → /employer-demo
│   └── [landing files]     → /
├── _redirects              # Netlify SPA fallbacks
└── _headers                # Security & CSP headers for Netlify
```

## Apps

### Landing (`apps/landing/`)
- Static HTML, no framework
- Multi-language (SK/EN) via vanilla JS i18n
- Dark/light mode via CSS custom properties
- Phone number signup form → `/api/submit`
- Demo popups embed the demo portals via iframes

### Student Demo (`apps/student-demo/`)
- React + Vite, `basename="/student-demo"`
- Demo mode detected via `demoMode.js` → bypasses Supabase
- **Onboarding flow** split into sub-components:
  - `components/onboarding/WelcomePhase.jsx`
  - `components/onboarding/UploadPhase.jsx`
  - `components/onboarding/ParsingPhase.jsx`
  - `components/onboarding/ReviewPhase.jsx`
  - `components/onboarding/ManualPhase.jsx`
  - `components/onboarding/ClimaxPhase.jsx`
- Pages: ForYou (swipe), Search, Applications, Profile, CandidateAuth

### Employer Demo (`apps/employer-demo/`)
- React + Vite, `basename="/employer-demo"`
- Demo mode → bypasses Supabase
- Pages: Dashboard, Listings, CreateListing, Candidates, Profile, EmployerAuth, Onboarding, Inquiry
- Components: SideNav (responsive desktop sidebar + mobile bottom nav), Chart, StatCard, etc.

### Student Live (`apps/student/`)
- Same structure as student-demo but fully Supabase-authenticated
- `demoMode.js` returns `false` in production

### Employer Live (`apps/employer/`)
- Same structure as employer-demo but fully Supabase-authenticated

## API Routes

### Public
| Method | Path | Description |
|--------|------|-------------|
| `POST` | `/api/submit` | Landing page email signup (rate-limited) |
| `POST` | `/api/auth/student/register` | Student account creation |
| `POST` | `/api/auth/employer/login` | Employer login → returns Supabase session |
| `POST` | `/api/auth/employer/inquiry` | Employer contact request |

### Student (Bearer token required)
| Method | Path | Description |
|--------|------|-------------|
| `GET` | `/api/jobs` | Fetch all job listings |
| `POST` | `/api/jobs/:id/view` | Track job view (non-fatal) |
| `POST` | `/api/applications` | Submit application + AI scoring |
| `GET` | `/api/profile` | Get student profile |
| `POST` | `/api/profile` | Upsert student profile |

### Employer (Bearer token required)
| Method | Path | Description |
|--------|------|-------------|
| `POST` | `/api/jobs` | Create new job listing |
| `DELETE` | `/api/jobs/:id` | Delete a job listing |
| `GET` | `/api/applications?company=X` | Fetch all candidates for company |
| `GET` | `/api/auth/employer/profile` | Get employer profile |
| `GET` | `/api/employer/analytics` | Dashboard analytics |

## Deployment
- **Host**: Netlify (static) for the `dist/` folder  
- **Backend**: Node.js Express on a server (or serverless with adapter)  
- **Database**: Supabase (PostgreSQL + Auth)
- The `netlify.toml` points build command to `npm run build` and publish to `dist/`

---

## Demo vs Live Separation
The demos are **completely isolated** from the live apps:
- Separate Vite apps in `apps/student-demo/` and `apps/employer-demo/`
- `demoMode.js` in each app controls whether Supabase is used
- Changes to live apps **do not affect** demo apps and vice versa
- Both have their own `dist/` build artifacts

## Database Schema (Supabase)
| Table | Purpose |
|-------|---------|
| `profiles` | Student profiles (name, location, skills, etc.) |
| `employer_profiles` | Employer profiles (name, industry) |
| `jobs` | Job listings created by employers |
| `applications` | Student-to-job applications with AI score |
| `submissions` | Landing page email signups |
| `user_roles` | Maps Supabase auth users to `candidate` / `employer` role |

---

## Key Design Decisions
- **Static route ordering**: Demo paths served before the landing page wildcard to prevent 404s
- **Graceful degradation**: Employer API endpoints return safe fallback data on DB errors
- **Mobile-first demos**: Bottom navigation bar with safe-area-inset support for iOS Safari
- **touch-action: pan-y**: Applied globally to fix iOS hold-to-scroll delay; swipeable cards get `touch-action: none`
