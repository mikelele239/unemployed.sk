# unemployed.sk — Platform Overview

> Tinder-style career platform for Gen Z in Slovakia.  
> Built with React (Vite), Express.js, and Supabase.  
> **Version**: 2.4.0 | **Last Updated**: 2026-05-06

---

## Architecture

```
unemployed.sk/
├── server.js               # Express backend — API proxy, auth, static serving
├── build.js                # Single-command build for all 4 apps + landing
├── apps/
│   ├── landing/            # Static HTML landing page (multi-lang SK/EN)
│   ├── student/            # Live student React app (Supabase-backed)
│   ├── employer/           # Live employer React app (Supabase-backed)
│   ├── student-demo/       # Isolated demo: no auth, mock data
│   └── employer-demo/      # Isolated demo: no auth, mock data
├── database/
│   └── scripts/            # SQL migration scripts (01-10)
├── docs/                   # Technical documentation
│   ├── PROJECT_OVERVIEW.md # Full architecture & feature reference
│   ├── DESIGN_SYSTEM.md    # Colors, typography, spacing tokens
│   └── FONTS.md            # Font stack reference
├── dist/                   # Production build output (generated by build.js)

│   ├── employer/           → /employer (employer portal)

│   └── [landing files]     → /

```

## Apps

### Landing (`apps/landing/`)
- Static HTML, no framework
- Multi-language (SK/EN) via vanilla JS i18n
- Dark/light mode via CSS custom properties
- Phone number signup form → `/api/submit`
- Demo popups embed the demo portals via iframes

### Student Portal (`apps/student/`)
- React + Vite, served at `/app`
- Supabase-authenticated with JWT
- **Onboarding**: CV upload → AI parse → profile review → skill selection
- **For You**: Tinder swipe cards (mobile) + split-view (desktop)
- **Search**: Job discovery with text query + filter drawer + category tabs + server-side employer search
- **Applications**: Track applied jobs, interview scheduling (accept/decline/counter-offer with ModernDatePicker)
- **Profile**: Edit name/bio/education/location, manage CV (single-CV model), upload avatar (signed URL), add/remove skills, profile strength meter
- **Company Profile**: Instagram-style company page with job listings + location display

### Employer Portal (`apps/employer/`)
- React + Vite, served at `/employer`
- Supabase-authenticated with JWT
- **Dashboard**: 5-card analytics layout with real-time metrics (active jobs, pipeline, interviews, conversion rate)
- **Listings**: CRUD for job postings with full edit modal (title, rate, type, model, location, description, requirements)
- **Candidates**: Browse & evaluate applicants with profile pictures, CV preview, interview scheduling (ModernDatePicker), hire/reject workflow
- **Profile**: Company info (name, description, website, location), logo upload, theme/language settings
- **Inquiry**: Public access request form for new employers

### Demo Apps (`apps/student-demo/`, `apps/employer-demo/`)
- Isolated from live apps — hardcoded mock data, no auth
- Changes to live apps do **not** affect demo apps

## API Routes

### Public
| Method | Path | Description |
|--------|------|-------------|
| `POST` | `/api/submit` | Landing page email/phone signup (rate-limited) |
| `POST` | `/api/auth/student/register` | Student account creation |
| `POST` | `/api/auth/employer/login` | Employer login → Supabase session |
| `POST` | `/api/auth/employer/inquiry` | Employer access request |
| `GET`  | `/api/employers` | List all employers (for student search) |
| `GET`  | `/api/company/:name` | Public company profile + job listings |

| Method | Path | Description |
|--------|------|-------------|

| `POST` | `/api/applications` | Submit application + AI scoring |

| `POST` | `/api/student/profile` | Upsert student profile (name, skills, avatar_url, cv_id) |

## Storage & File Management

- **Bucket**: `cvs` (private) — stores CVs, avatars, and employer logos
- **File Structure**: `{user_id}/avatar.{ext}`, `{user_id}/{timestamp}_{filename}.pdf`, `{user_id}/logo.{ext}`
- **URL Strategy**: All file URLs use **signed URLs** (private bucket) — never public URLs
- **Avatar Resolution**: On page load, avatar files are dynamically resolved from storage with fresh signed URLs to avoid stale/expired URLs
- **Single CV Model**: Only one CV per student; old CVs are deleted on new upload

---

## Security Model

- **RLS Bypass**: All sensitive operations go through `server.js` using `SUPABASE_KEY` (service role)
- **JWT Validation**: `getUserFromToken()` validates tokens on every protected request
- **Portal Isolation**: Separate Supabase storage keys prevent cross-portal session conflicts
- **CSP Headers**: Content Security Policy restricts connections to `*.supabase.co` (https + wss)
- **File Access Control**: Server blocks access to `.env`, `package.json`, database files

---

## Key Design Decisions

- **Server proxy for all writes**: Profile saves, application updates, and analytics all route through `server.js` to bypass RLS with the service role key
- **Signed URLs everywhere**: The `cvs` bucket is private; all file URLs are generated via `createSignedUrl()` with appropriate TTLs
- **Single CV per student**: Simplifies the UX — upload replaces previous CV, no list management needed
- **Dynamic avatar resolution**: On mount, components resolve avatars from storage with fresh signed URLs rather than relying on potentially stale DB values
- **Mobile-first**: Bottom navigation with safe-area-inset support for iOS Safari
- **touch-action: pan-y**: Applied globally to fix iOS hold-to-scroll delay; swipeable cards get `touch-action: none`
